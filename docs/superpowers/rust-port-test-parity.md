# Rust port -- test parity

One row per Python test file under `tests/` (239 files at the top level;
`tests/adversarial/` is wave 5.2 and is noted at the bottom). Regenerated by
the test-parity sweep on 2026-08-22.

## Method

Every `def test_*` in each Python file is looked up as a Rust `fn` of the
same name across `crates/*/src/**` and `crates/*/tests/**`. The port
convention keeps the names identical, so an exact name match is the parity
signal.

A Rust namesake counts as **live** only if it is not `#[ignore]`d. Many
ported files carry `#[ignore]`d empty stubs that name a case and its blocker;
those are counted separately, because a stub is a placeholder, not coverage.

Classes:

- **PORTED** -- every Python case has a live Rust namesake.
- **PARTIAL** -- some do. The counts column says how many are live, how many
  are `#[ignore]`d stubs, and the Python total.
- **TOOLS-ONLY** -- covers a `tools/*.py` script, which stays Python by
  design (spec: "Out of scope (stays Python): tools/"). Must NOT be ported.
- **NOT PORTED** -- no live Rust case from this file.
- **HELPER** -- fixtures or a harness imported by other files, not a test file.

crate, so those cases can never run where they are listed: their home is
`crates/freight-fate/tests/`. 117 of them already had a live twin there and
have been removed. What is left is either genuinely unported or waiting on a
