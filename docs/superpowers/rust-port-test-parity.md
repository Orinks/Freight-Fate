## Method

Every `def test_*` in each Python file is looked up as a Rust `fn` of the
same name across `crates/*/src/**` and `crates/*/tests/**`. The port
convention keeps the names identical, so an exact name match is the parity
signal.

A Rust namesake counts as **live** only if its file is REGISTERED and it is
not `#[ignore]`d. Registration is new and is the same trap in a new shape: the
integration tests are one binary now, and a file in `tests/it/` that has no
`mod` line in `tests/it/main.rs` is never compiled and never run, while the
sweep above still finds its `fn test_*` and counts it. A file lost its `mod`
lines twice on 2026-08-24 while several agents edited `main.rs` at once, and
the only visible symptom was a filter matching zero tests. Check the count in
the run output by name, never a green run.

A Rust namesake counts as live only if it is not `#[ignore]`d. Many
ported files carry `#[ignore]`d empty stubs that name a case and its blocker;
those are counted separately, because a stub is a placeholder, not coverage.
Counting them as coverage would inflate parity by hundreds of cases, which
is the illusion this audit exists to prevent.

A case with a real body that is `#[ignore]`d because the PORT is wrong is
counted the same way: not live. The reason string has to name the defect
(`PORT BUG:` plus the evidence), so the difference between "nobody wrote it"
and "it is written and the port fails it" is readable without running
anything -- but neither is coverage, because neither runs.

The sweep reads `fn test_*` out of the source, so a stub written by a
`macro_rules!` (which emits `fn $name`) is invisible to it. One such block hid
49 cases until this sweep; it has been unrolled. Never generate `#[ignore]`d
stubs from a macro -- the audit cannot see them, which is the whole point of
having one.

Classes:

- **PORTED** -- every Python case has a live Rust namesake.
- **PARTIAL** -- some do. The counts column says how many are live, how many
  are `#[ignore]`d stubs, and the Python total.
- **TOOLS-ONLY** -- covers a `tools/*.py` script, which stays Python by
  design (spec: "Out of scope (stays Python): tools/"). Must NOT be ported.
- **NOT PORTED** -- no live Rust case from this file.
- **HELPER** -- fixtures or a harness imported by other files, not a test file.

written inline, so the Rust check masks every string literal, char literal and
comment to spaces (a real raw string lives in `driving_core/constants.rs`),
balances the call's parentheses over what is left, and follows a bare `opts` /
`opts()` argument back to its `let` or its `opts.category =` inside the
enclosing function. Verified by deleting one real `.category(...)` and
watching it report that line, so it is not a sweep that always passes.

`test_an_engine_stall_speaks_at_urgent_only_as_safety` replaced Python's
monkeypatched `TruckState.update` with the stall the game actually models: a
manual box launched in sixth with the clutch out, driven in real frames until

scenario at all three rungs. Python patched `Rig.__init__` to force the rung

every rung sound identical.

`test_every_trip_event_kind_is_classified` iterated the enum in Python, which
Rust cannot do. The list of kinds is written out and guarded by an exhaustive
`match` beside it: add a variant and the file stops compiling, so the list
cannot silently fall behind the enum -- which is the only thing that case is
for.

Two counts had to be read off `ctx.message_log` rather than the voice, and
both are noted at the use site: the Rust capture sits BELOW the pacer, so a

### The flake in `states_driving_turns`

`test_safe_speed_folds_in_the_bend` was not a threading problem. Measured over
50 runs each, before the fix:

| | Failure rate |
|---|---|
| the one test alone, fresh process | 7 / 50 |
| the whole binary, default threads | 3 / 50 |

Failing alone at a higher rate than in parallel rules out shared state between
threads. The cause is that the Rust port of
`driving_feature_helpers.quiet_trip` kept only half of it. The Python helper
empties the road **and** pins `driving.weather.current = WeatherKind.CLEAR`;
the Rust `a_drive` helpers emptied the road and left the sky alone. A drive
built with `trip_seed = None` seeds itself off the wall clock, so the weather
is a fresh random draw every run -- and an ice day caps the safe speed at
20 mph, under the bend's 25 mph advisory, so the fold the test measures never
happens and the line comes back `Safe speed 20 miles per hour.`

Five helpers had the same half-port (`states_driving_turns.rs`,
`states_driving_controls.rs`, `states_driving_events.rs`,
`states_driving_updates.rs`, `states_driving_menus_support/mod.rs`); all five
now pin the weather. After the fix: 0 of 60 alone and 0 of 30 for the whole
binary.

### The `playtest_harness` environment-lock flake

`TestApp` holds a process-global mutex for the app's whole life, so every test
in a binary queues on it, and `env_lock()` panicked after a 30-second wait to
catch a test that deadlocks itself by building a second `TestApp`. But
`playtest_harness.rs` runs 32 real drives back to back in 39 seconds of wall
clock: whichever test was last in that queue waited longer than the deadline
and failed, naming itself rather than the cause. That is why it named a
different test each run.

The guard now records the owning thread. Asking for a lock this thread already
holds panics immediately with the same self-deadlock message; waiting on
another thread is not a deadlock and no longer has a wall-clock deadline (a
ten-minute backstop remains, for a genuine hang).
